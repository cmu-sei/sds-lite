Installation options: NPM or CDN
Recommended

NPM

Authenticate with GitHub Packages once, then install and import CSS and automatic behavior. 

npm install @cmu-sei/sds-lite

import '@cmu-sei/sds-lite/sds.css'
import '@cmu-sei/sds-lite/auto'
NPM guide
No build step

CDN

Use version-pinned CDN links in a standalone page when you do not need a build tool. 

<link rel="stylesheet"
  href="https://cdn.jsdelivr.net/gh/cmu-sei/sds-lite@v0.2.3/dist/sds.css">
<script type="module"
  src="https://cdn.jsdelivr.net/gh/cmu-sei/sds-lite@v0.2.3/dist/auto.js"></script>
CDN guide
Then write HTML Add data-sds-root to a container. Native headings, links, buttons, and form controls work immediately.

    Prose

    Long-form content

    Dependency-free typography for articles, documentation, and generated rich text.

    Prose API and example

    Typography

    • .sds-prose applies article typography
    • data-sds-size: sm, md, lg
    • data-sds-tone: neutral, accent, info, success, warning, danger
    • .sds-not-prose opts out nested content

    Article content

    <article class="sds-prose" data-sds-tone="info">
  <h1>Article title</h1>
  <p class="sds-prose-lead">A short introduction.</p>
  <p>Semantic HTML receives the complete typography treatment.</p>
</article>

    Building resilient software

    Good systems make the correct path obvious while retaining the flexibility experts need.

    Prose supports strong text, emphasis, inline links, inline code, and keyboard input such as Command + K.

    Clear information hierarchy

    Headings, paragraphs, lists, quotations, code, media, and tables share predictable vertical rhythm.

    Ordered work

    1. Define the outcome.
    2. Implement the smallest complete path.
      1. Preserve native semantics.
      2. Verify observable behavior.
    3. Document the interface.

    Supporting principles

    • Keep interfaces small.
    • Keep related implementation local.
    • Prefer browser standards.
    A design system should reduce the knowledge required to produce a consistent interface.

    Dropdowns, floating content, disclosures, and overlays

    Browser primitives provide the semantics; SDS adds a small declarative enhancement layer.

    Overlays API and example

    Floating surfaces

    • sds-dropdown and sds-popover widths: sm, md, lg, xl, 2xl, auto
    • placement: block-start, block-end, inline-start, inline-end, with optional start/end alignment
    • offset: nonnegative pixels

    Dialogs and panels

    • dialog[data-sds-width]: sm, md, lg, xl, 2xl
    • panel[data-sds-side]: left, right, bottom
    • panel[data-sds-width]: sm, md, lg, xl
